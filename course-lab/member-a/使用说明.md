# 衣橱管家：成员 A 的代码与使用说明

本代码包含 Java＋XML Android 应用和 Java Spring Boot 账号后端。
账号功能连接真实数据库；B、C、D、E 的业务页面目前为接入占位页，没有伪造衣物或统计数据。

## 1. 文件位置

- `android/`：用 Android Studio 打开的项目根目录。包含 Gradle Wrapper。
- `server/`：账号后端、数据库初始化脚本、接口测试及独立说明。
- `releases/`：验证后打包的 APK 和后端 JAR（如已生成）。
- `screenshots/`：模拟器实拍页面（如已生成）。
- `团队接入说明.md`：给 B—E 成员的协作约定。

现有 Desktop 工程没有被覆盖。本项目使用独立包名 `com.example.wardrobemanager`。

## 2. 从源码启动后端

GitHub 保存源码，不包含 APK、JAR、账号数据库或本机配置。
先安装 JDK 17 或以上与 Maven 3.6.3 或以上，并将 Maven 加入 PATH。
在本目录的 `server` 文件夹打开 PowerShell，执行：

```powershell
mvn package
java -jar target/wardrobe-account-server-1.0.0.jar
```

Windows 也可双击 `server/START_SERVER.cmd`，它会在缺少 JAR 时先调用 Maven 编译。
首次编译需要联网下载依赖。服务器默认使用 8080 端口，启动后保留窗口。
默认 H2 文件数据库在 `server/data` 创建，不进入 Git。
如果全组使用 MySQL，参照 `server/README.md` 切换配置，一次运行只连接一个数据库。
该目录是独立课程 A 模块；仓库根目录的 Kotlin/Compose 应用另有自己的运行说明。

## 3. 打开 Android 工程

1. Android Studio → Open，选择 `android` 文件夹。
2. 等待 Gradle 同步。项目沿用你电脑已有的 AGP 9.5.1、Gradle 9.6.0、Android API 37 配置。
3. 换电脑或改了目录时，让 Android Studio 配置本机 Android SDK，不要复制他人的 `local.properties`。
4. 在设置的 Gradle JDK 中选择 Android Studio 自带的 JDK；不要强制使用仅 Java 17 的 Gradle 运行环境。
5. 选择 Android 模拟器，点击 Run。

应用在 Android 7.0（API 24）及以上运行，界面文字为英文。
不需要把这些 Java/XML 文件复制到原来的 Kotlin Compose 工程。

## 4. 第一次使用

1. 启动后端，打开应用。
2. 点击 **Create account** 进入注册。
3. 填写昵称、账号、密码及确认密码，完成注册。
4. 返回登录页，使用刚创建的账号登录。
5. 主页可打开四个模块入口；**My profile** 可修改昵称。
6. **Sign out** 会请求服务器撤销当前登录，再返回登录页。

没有预置账号，需要先注册。
账号使用 3—32 位英文字母、数字或下划线，不区分大小写。
密码为 8—72 个 UTF-8 字节，建议课堂测试使用至少 8 位英文字母和数字；密码不会自动去掉空格。
昵称为去掉首尾空格后 1—40 个 UTF-16 字符。

## 5. 手机如何连接电脑

Android 模拟器默认地址已经设为 `http://10.0.2.2:8080`。
Android 17 首次连接本地服务器时会请求本地网络访问权限，请允许；拒绝后可以在应用权限设置中重新开启。
登录页的 **Connection settings** 可以修改地址，只填写服务器根地址，不加 `/api`。

USB 真机调试可在电脑执行：

```powershell
adb reverse tcp:8080 tcp:8080
```

然后将应用连接地址设为 `http://127.0.0.1:8080`。
如使用局域网真机，手机和电脑处于同一网络，填写电脑局域网 IP 地址，并确认防火墙允许本地测试连接。
手机的 `localhost` 代表手机自己。

本地 HTTP 仅在 debug 构建允许，release 构建禁止明文传输。正式部署须配置真实 HTTPS 地址。
不要在应用中存放数据库账号密码。

## 6. MVC 在哪里

Android：

- `view/` 与 `res/layout/`：页面、界面渲染与生命周期协调。
- `controller/AccountController.java`：操作协调、输入检查、异步调度与结果分发。
- `model/User.java`：用户数据。
- `model/AccountRepository.java`：网络数据访问。
- `model/SessionStore.java`：以 Android Keystore 密钥加密保存登录凭证，不保存密码。
- `model/EndpointStore.java`：统一后端地址设置。

后端：

- Controller：接收 HTTP 请求并返回 JSON。
- Service：账号、身份和会话业务规则。
- Repository：参数化数据库操作。

网络访问在后台线程执行；页面销毁后丢弃回调，避免更新已销毁的页面。
请结合老师 Lecture 14 解释上述职责，不要只展示文件夹名称。

## 7. A 的验收清单

- 注册一个账号；重新启动后端后仍能登录。
- 相同账号的不同大小写不能重复注册。
- 错误密码不能登录。
- 修改昵称，返回主页显示新昵称。
- 退出后需要重新登录；旧登录凭证不能继续访问后端。
- 第二个账号看不到第一个账号的资料。
- 输入为空、密码不一致、网络断开时有明确提示。
- B—E 的导航入口正常，尚未实现的页面明确显示未接入。

## 8. 常见问题

**Cannot reach the server**：确认后端正在运行，检查连接地址和端口。模拟器优先用默认地址。

**8080 已占用**：先确认是否已启动过本项目。可以设置后端 PORT 环境变量并同步修改应用地址。

**Gradle 同步失败**：保留第一条具体错误；确认 SDK/API 37 和自带 JDK 配置。首次同步可能需要下载依赖。

**数据库表结构不一致**：不要删除全组数据库。先与 B—E 对齐字段和约束，再做迁移。

**离线时不能退出**：当前退出功能要求服务器确认撤销登录。恢复连接后重试。返回登录页或修改连接地址只会清除本地凭证，不等于撤销远端会话，远端仍按有效期到期。

代码是 A 模块的开发起点，不包含完整衣物、搭配、洗护和统计业务。账号找回、限流和正式部署配置也不在本次交付范围。
